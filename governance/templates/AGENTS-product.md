# AGENTS.md

本文件是 AI Agent 在本仓库工作的入口。开始修改前，必须先理解项目目标、架构边界、数据风险和验证方式，不得只依据当前对话或局部代码直接实现。

## 1. 修改前必读

按顺序读取：

1. 当前 Issue、PR 描述和验收标准；
2. `README.md`；
3. `ARCHITECTURE.md`（如存在）；
4. 本文件；
5. 与修改模块相关的工程文档、测试和同类实现。

如这些资料相互冲突，应停止扩大修改范围，在 PR 中明确冲突与采用的判断。

## 2. 风险等级

开始实现前声明风险等级：

- **P0**：生产故障、数据损坏、严重安全或隐私问题；
- **P1**：认证权限、数据迁移、删除导出、同步、发布与外部接口；
- **P2**：重要功能、跨模块改造、明显性能或兼容风险；
- **P3**：低风险 UI、文档、测试与内部整理。

P0/P1 必须有关联 Issue、失败路径测试、独立审查和可执行回滚。

## 3. 强制流程

### 调查

先只读并确认：

- 相关文件与调用链；
- 现有可复用机制；
- 数据、接口、权限、部署和兼容影响；
- 已确认事实、推断和未知项；
- 最小修改范围。

禁止看到局部实现后立即建立第二套 API、Store、缓存、状态机或错误处理机制。

### 计划

计划至少写明：

- 修改哪些文件或模块；
- 为什么在这里修改；
- 如何验证；
- 哪些相邻问题明确不处理；
- 如何独立提交和回滚。

### 实现

- 一个 PR 只解决一个主要问题；
- 不混合功能、无关重构和全局格式化；
- 不为未确认的未来需求提前抽象；
- 发现相邻问题时建立 Issue，不顺手扩大范围；
- 提交说明使用中文；
- 默认从最新正式主分支创建分支并通过 PR 合并。

### 测试

以下逻辑优先先写失败测试：

- 权限与账号状态；
- 数据转换、同步、唯一性和状态机；
- 重试、超时、冲突、中断恢复和缓存；
- 导入导出、删除、路径、远端存储与外部接口；
- 安全、隐私和 AI 生成操作。

禁止为了让测试通过而改变真实业务语义。

### 独立审查

完成实现后至少进行：

1. 规格审查：是否满足 Issue、验收标准与非目标；
2. 代码审查：是否存在重复机制、权限、隐私、事务、并发、性能和兼容问题。

不得仅使用实现阶段的同一上下文自行宣布无问题。审查应重新读取 Issue、完整 diff、测试和架构规则。

### 完成验证

完成前提供实际证据：

- 执行过的命令与结果；
- 失败路径和边界条件；
- 构建、测试和部署验证；
- 数据迁移或远端服务验证（适用时）；
- 回滚方式；
- 尚未确认的假设和剩余风险。

“看起来正确”或“CI 应该会通过”不属于验证证据。

## 4. Git 与合并

- 正式主分支是唯一发布事实来源；
- 不直接推送正式主分支；
- 默认使用 squash merge；
- 合并后删除功能分支；
- 不强制推送改写已公开审查历史，除非明确处理分支事故；
- 堆叠 PR 默认不超过 2～3 层，超过时先合并稳定基础层。

## 5. 数据与安全

- Token、密码、密钥、生产配置和用户隐私数据不得进入代码、测试、日志、截图、Issue、PR 或 Artifact；
- 前端隐藏按钮不是权限控制；
- AI 或远端服务返回内容必须视为不可信输入；
- 删除、覆盖、批量变更和同步必须有明确确认、边界、失败恢复与审计；
- 不向客户端暴露内部路径、底层凭据或敏感异常。

## 6. 架构规则

- 优先复用现有模块、组件和依赖方向；
- 新基础设施或改变核心依赖方向前先记录架构决策；
- 页面或 Controller 不承载复杂业务规则；
- 不因局部需求擅自引入新的数据库、消息队列、缓存或服务拆分；
- 公共模块不得反向依赖具体业务页面。

## 7. 停止条件

遇到以下情况应停止扩大实现并在 PR 中说明：

- 需求与现有数据模型或安全边界冲突；
- 无法验证真实数据库、远端服务或平台行为；
- 需要修改未在范围内的核心架构；
- 发现凭据、隐私数据或高风险生产配置；
- 上游堆叠 PR 尚未稳定，继续开发会扩大返工范围。
